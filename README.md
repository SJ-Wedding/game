# 균열 아레나 (Rift Arena)

PC 브라우저에서 설치 없이 바로 플레이하는 **2D 탑다운 액션 로그라이크 RPG**의 MVP입니다.
아레나 하나에서 몰려오는 괴물을 쓰러뜨리고, 레벨이 오를 때마다 강화 3개 중 1개를 골라 빌드를 만들고,
**전투 시간 13:30에 등장하는 보스 '잿불 군주'를 15:00 전에 처치하면 승리**합니다.

- 기술 스택: TypeScript · Phaser 3 · Vite (배포물은 정적 파일만 있으면 됨, 서버·계정 불필요)
- 기획 문서: [`docs/GAME_DESIGN.md`](docs/GAME_DESIGN.md)
- 플레이 시간 측정·검증 기록: [`docs/PLAYTEST.md`](docs/PLAYTEST.md)
- 변경 이력: [`CHANGELOG.md`](CHANGELOG.md)
- 이전 프로토타입(바닐라 JS, 별개 게임)은 [`legacy/rift-judge-prototype/`](legacy/rift-judge-prototype/)에 보관되어 있으며 빌드에 포함되지 않습니다.

## 조작

| 입력 | 동작 |
| --- | --- |
| `W` `A` `S` `D` (방향키도 가능) | 이동 |
| (자동) | 사거리 안의 **가장 가까운 적을 자동 조준·자동 공격** — 대상에 청록 꺾쇠 표시 |
| `Space` | 회피 — 짧게 돌진하며 잠깐 무적 |
| `Tab` | 상태창 — 능력치(시작·영구 강화·현재)와 이번 판 강화 확인 (보는 동안 시간 정지) |
| `Esc` | 일시정지 / 재개 |
| `1` `2` `3` | 레벨업 강화 선택 (클릭도 가능) |
| `R` (레벨업 화면) | 선택지 새로고침 (한 판 2회, 영구 강화로 최대 4회) |
| `Enter` / `Space` / `R` | 결과 화면에서 바로 다시 시작 |

## 성장 구조 (v0.3.0)

- **영구 성장**: 판이 끝나면 토큰(◆)을 받습니다 — 생존 1분당 2, 일반 처치 50마리당 1, 엘리트 1마리당 5, 승리 30.
  타이틀의 **강화 상점**에서 영구 강화(최대 체력·공격력·공격 속도·이동 속도·회피 대기·흡수 범위·경험치, 각 5단계)와
  해금(새로고침 +1·부활·시작 강화·행운)을 삽니다. 시작 능력치는 낮게 시작하고 영구 강화로 되찾는 구조입니다.
- **레벨업 보상 등급**: 카드마다 일반(65%)·희귀(25%)·영웅(8%)·전설(2%) 등급이 붙고, 효과가 ×1·×1.5·×2·×3 이 됩니다.
  레벨이 오를수록, 영구 강화 '행운'을 살수록 상위 등급이 잘 나옵니다.
- **처치 드랍**: 회복 물약(1.5%, 엘리트는 100%), 자석(0.4%, 맵의 경험치 보석을 모두 끌어옴), 균열 폭탄(0.25%, 화면 안 적에게 큰 피해).
- **초반 레벨업**: 첫 레벨업은 경험치 8로 도달합니다. Lv 2~5는 필요한 경험치가 절반입니다. 보석을 연달아 주우면 합산된 실제 획득량을 HUD에 표시합니다.

## 특수 무기

첫 레벨업에서는 서로 다른 특수 무기 3개 중 하나를 고릅니다. 이후 레벨 5·8·11처럼 세 레벨마다 새 특수 무기가 후보에 등장합니다.
레벨 3·6·9처럼 세 레벨마다 보유한 특수 무기를 강화할 수 있습니다. 무기는 기본 자동 사격과 함께 작동하며 최대 Lv 3까지 오른 단계마다 기본 무기 피해에 20%씩 더해지고, 연쇄 대상·탄환 수·설치 주기·범위 등 무기마다 다른 효과가 강화됩니다. 카드에서 적용 전후 수치를 볼 수 있습니다.
일반 강화 **균열의 통찰**은 등급에 따라 경험치 획득량을 10·15·20·30% 늘리며 최대 3회 선택할 수 있습니다.

- **연쇄 번개 · 관통 창 · 낙뢰 표식** — 뭉친 적, 일렬로 선 적, 같은 적에게 이어지는 기본탄을 각각 활용합니다.
- **균열 지뢰 · 서리 포탑 · 화염 발자국 · 균열 장벽** — 설치 위치, 이동, 회피 경로에 따라 피해를 줍니다.
- **회전 칼날 · 부메랑 도끼 · 메아리 사격 · 중력 구체 · 처치 전염** — 접근, 귀환 경로, 이전 사격 위치, 적 끌어모으기, 연쇄 처치를 각각 활용합니다.

몬스터 처치 경험치는 그림자 망령 1, 가시 포자 3, 뿔 돌격수 4, 균열 수호자 40입니다.

경험치 영구 강화의 1~5단계 보너스는 +12%, +19%, +25%, +30%, +35%입니다.

전투 중 오른쪽 위 **조합식** 버튼이나 `C` 키로 조합식을 바로 열 수 있습니다. 3분부터 원거리 사거리가 점차 늘어나며, 5분부터 기본탄은 일반 적을 최대 3마리 관통합니다.

### 합체 조합식

재료 무기 두 개가 모두 Lv 3이면 레벨업이나 수호자의 무기 보상에서 합체를 고를 수 있습니다. 합체기는 즉시 Lv 3으로 제공되고 재료 무기 두 개의 공격을 대신해 주기적으로 발동합니다. 두 재료의 등급별 피해 보너스 평균을 계승하고, 후반 몬스터의 추가 피해 감소 효과를 50% 관통합니다.

| 합체기 | 재료 |
| --- | --- |
| 뇌광 연쇄 | 연쇄 번개 + 낙뢰 표식 |
| 빙결 지뢰진 | 균열 지뢰 + 서리 포탑 |
| 쌍날 폭풍 | 회전 칼날 + 부메랑 도끼 |
| 잿불 균열 | 화염 발자국 + 균열 장벽 |
| 잔영 관통포 | 관통 창 + 메아리 사격 |
| 검은 역병 | 중력 구체 + 처치 전염 |

8분부터 몬스터의 출현 수와 동시 출현 한도가 늘고, 몬스터가 받는 피해는 15% 감소합니다. 이 피해 감소율은 분당 5.5%p씩 최대 45%까지 증가합니다. 9분 이후 등장하는 뿔 돌격수와 균열 수호자는 기본탄 피해를 추가로 줄입니다.

일반 강화 **행운의 별**은 등급에 따라 행운을 1~3 올립니다. 상점의 영구 행운은 단계마다 +1이며, 일반·특수 무기 후보 모두의 등급 확률에 적용됩니다. 다른 행운 보너스 없이 행운 5일 때 카드 1장의 영웅·전설 확률은 합계 30%입니다. 무기 등급은 해당 무기에 단계별 추가 피해를 부여합니다.

## 유물

- 레벨 3에서 초반 전투용 유물 6종 중 3개가 제시됩니다. 이후 레벨 5·10·15처럼 5레벨마다 일반 강화에 이어 유물을 하나 고릅니다. 중간 보스인 균열 수호자를 처치하면 유물을 먼저 고른 뒤, 전용 무기 보상에서 특수 무기 획득·강화 또는 준비된 합체를 선택합니다. 보유 무기의 조합 재료가 우선 등장합니다.
- 전투 오른쪽 위나 일시정지 화면에서 보유 유물에 마우스를 올리면 효과가 표시됩니다. Tab으로 연 상태창에서는 마우스와 키보드 포커스로 확인할 수 있습니다.
- 승리 후 다음 판을 누르면 계승 팝업이 열립니다. 유물을 최대 3개 고르고 시작하거나, 유물 없이 시작할 수 있습니다. 이전에 계승한 유물도 다시 선택할 수 있고, 누적 처치·충전·발동 횟수는 새 판에서 초기화됩니다.

유물은 모두 71종입니다. 효과 문구와 수치는 `src/config/relics.ts`, 동작은 `src/core/relics.ts`(특수 무기 전용은 `src/core/weapons.ts`)에 있습니다. 탐욕의 황금 주사위·점술가의 카드·네잎 클로버 브로치·서두른 초대장은 다음 판으로 가져갈 수 없습니다.

균열 수호자 유물 **삼중 선택의 인장**은 판마다 처음 장착할 때 보너스 강화 선택 화면을 세 번 엽니다. 일반 레벨업 횟수는 소모하지 않습니다.

결과 화면의 공격별 평균 DPS는 저항과 유물 효과를 적용한 적중 피해량을 해당 판의 전투 시간으로 나눈 값입니다. 총 피해량과 평균 DPS에는 적의 남은 체력을 초과한 피해도 포함됩니다. 기본 사격, 특수 무기, 합체의 공명 폭발, 균열 폭탄 피해가 표시됩니다.

## 빠른 시작

Node.js 20 이상이 필요합니다.

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 `http://localhost:5173` 을 엽니다. `npm run dev` 에서는 **개발 모드**가 자동으로 켜집니다(아래 참고).

| 명령 | 설명 |
| --- | --- |
| `npm run dev` | 개발 서버 (코드 수정 시 자동 새로고침, 개발 모드 ON) |
| `npm run build` | 타입 검사 후 배포용 정적 파일을 `dist/` 에 생성 |
| `npm run preview` | `dist/` 를 `http://localhost:4173` 에서 미리보기 |
| `npm test` | 단위 테스트 (전투 규칙·시간·보스·강화·저장·밸런스 회귀) |
| `npm run test:e2e` | 실제 브라우저 자동 테스트 (빌드 → 미리보기 서버 자동 실행, 약 2분) |
| `npm run test:e2e:full` | 봇이 실제 키보드·마우스 입력으로 15분 한 판을 끝까지 플레이하며 시간 측정 (실시간 15분) |
| `npm run sim` | 브라우저 없이 봇으로 여러 판을 빠르게 시뮬레이션해 밸런스 요약 출력 (수 초) |
| `npm run typecheck` | 타입 검사만 |

> 브라우저 자동 테스트는 Playwright 를 씁니다. 처음 한 번은 `npx playwright install chromium` 으로 브라우저를 받아야 할 수 있습니다.

## 배포 (정적 호스팅)

```bash
npm run build
```

**`dist/` 폴더 안의 파일 전체**를 정적 호스팅에 올리면 끝입니다. 상대 경로(`base: './'`)로 빌드되므로
도메인 루트든 하위 경로(`https://아이디.github.io/저장소/`)든 그대로 동작합니다.
플레이어는 URL 을 열기만 하면 되고 계정·설치가 필요 없습니다.

- **GitHub Pages (이 저장소 설정)**: `.github/workflows/deploy.yml` 이 `main` 에 푸시될 때마다 `npm test` → `npm run build` 후 `dist/` 를 자동 배포합니다.
  처음 한 번 저장소 **Settings → Pages → Build and deployment → Source** 를 **GitHub Actions** 로 바꿔 주세요.
  ("Deploy from a branch" 로 두면 빌드 전 소스가 그대로 올라가 빈 화면이 됩니다.) 배포 주소: `https://<계정>.github.io/<저장소>/`
- **Netlify / Cloudflare Pages / Vercel**: 빌드 명령 `npm run build`, 게시 폴더 `dist`.
- **S3·사내 웹서버 등**: `dist/` 를 그대로 복사.

주의: `dist/index.html` 을 파일 탐색기에서 더블클릭(`file://`)하면 브라우저 보안 정책 때문에 실행되지 않습니다. 반드시 웹 서버(위 호스팅 또는 `npm run preview`)로 여세요.

## 폴더 구조와 책임

책임을 네 갈래로 나눴습니다. **전투 규칙은 Phaser·DOM 을 전혀 모르기 때문에** Node 에서 그대로 테스트·시뮬레이션할 수 있습니다.

```
src/
  config/        ← 콘텐츠·밸런스 설정 (숫자와 데이터만, 로직 없음)
  core/          ← 전투 규칙 (순수 TypeScript, 고정 틱 시뮬레이션)
    sim.ts         GameSim: 시간·스폰·충돌·경험치·레벨업·승패
    enemies.ts     일반 적 3종 + 엘리트 행동
    boss.ts        보스 행동(패턴·페이즈)
    upgrades.ts    강화 후보 추첨·중첩 한도
    stats.ts       기본 능력치 + 강화 → 최종 능력치
    progression.ts 경험치 곡선
    rng.ts         시드 난수 (스폰·강화·AI 스트림 분리)
    bot.ts         밸런스 측정용 자동 플레이어
  render/        ← 화면 그리기 (Phaser). 입력 수집도 여기서
    GameScene.ts   월드·적·투사체·예고 그리기, 키보드·마우스 → InputState
    palette.ts     색상 규칙
  ui/            ← DOM 화면 UI
    hud.ts         체력·경험치·남은 시간·회피 대기·처치 수·보스 체력·안내 문구
    screens.ts     타이틀 / 일시정지 / 레벨업 / 결과 화면
  storage/       ← 브라우저 저장 (localStorage, 버전·검증)
    save.ts
  app/App.ts     ← 화면 흐름(타이틀→전투→레벨업/일시정지→결과→재시작), 전역 입력(Esc 등)
  audio/sfx.ts   ← WebAudio 합성 효과음 (음원 파일 없음)
  dev/           ← 개발 모드 옵션(시드·보스 구간 시작·무적), 디버그 훅 window.__rift
  main.ts        ← 조립 (저장 읽기 → App → Phaser.Game)
tests/           ← 단위 테스트 (Vitest)
e2e/             ← 브라우저 테스트 (Playwright)
scripts/simulate.ts ← 밸런스 시뮬레이션
```

데이터 흐름: `GameScene`(입력 수집) → `App.frame()` → `GameSim.advance()`(전투 중일 때만) → 이벤트 → 효과음·HUD·이펙트 → `GameScene`(그리기)

## 설정 파일 가이드 — 무엇을 바꾸면 무엇이 달라지나

모든 밸런스 값은 `src/config/` 에 있습니다. 시간 단위는 **전투 시간(초)** 입니다(일시정지·강화 선택 중에는 흐르지 않음).

### `src/config/run.ts` — 한 판의 시간 구조
| 값 | 기본 | 바꾸면 |
| --- | --- | --- |
| `timeLimit` | 900 (15:00) | 이 시각까지 보스를 못 잡으면 시간 초과 패배. 한 판 최대 길이 |
| `bossAt` | 810 (13:30) | 보스 등장 시각. 줄이면 보스전이 길어지고, 늘리면 보스를 잡을 시간이 줄어듦 |
| `tickRate` | 60 | 판정 정밀도(초당 틱). 보통 그대로 둠 |
| `maxTicksPerFrame` | 6 | 느린 프레임에서 한 번에 따라잡는 최대 틱. 키우면 렉 후 시간이 튀고, 줄이면 느린 기기에서 게임이 느려짐 |

### `src/config/spawns.ts` — 적 생성 시간표
- `SPAWN_PHASES`: 구간별(`from`~`to`) 생성 규칙
  - `interval: [시작, 끝]` — 몇 초마다 생성할지. 작을수록 적이 많아짐 (구간 안에서 선형 변화)
  - `batch` — 한 번에 생성할 수
  - `maxAlive` — 동시에 살아 있는 적 상한. **낮추면 이동·회피 공간이 넓어짐**
  - `weights` — 종류별 비율. 예) `{ chaser: 3, charger: 1 }` 이면 4마리 중 1마리꼴로 돌진형
  - `announce` — 구간이 시작될 때 화면에 띄우는 안내 문구
- `SPAWN_EVENTS`: 특정 시각 1회 이벤트. 현재 엘리트 등장(2:00, 4:00, 6:30, 9:00, 11:30)

### `src/config/enemies.ts` — 적 능력치
- `ENEMY_CONFIG.chaser` (그림자 망령, 추격형) / `charger` (뿔 돌격수, 돌진형) / `spitter` (가시 포자, 원거리형) / `elite` (균열 수호자)
  - `hp`, `speed`, `radius`, `contactDamage`, `xp`(처치 시 경험치)
  - 돌진형: `windup`(예고선 표시 시간 — **늘리면 피하기 쉬움**), `dashSpeed`·`dashTime`(돌진 거리 = 속도×시간), `cooldown`
  - 원거리형: `preferredRange`(유지 거리), `fireInterval`, `windup`(발사 전 부풀어 오르는 예고), `projectileSpeed`·`projectileDamage`
  - 엘리트: 돌진과 원형 파편(`burstCount`)을 번갈아 사용
  - `attackNames`: 사망 원인으로 결과 화면에 표시되는 이름
- `ENEMY_SCALING`: 분당 기본 체력 +9%. 9분 이후 등장하는 돌격수·수호자는 기본탄 피해 30%를 줄입니다. 최종 보스는 기본탄 피해를 25% 줄입니다. 시간에 따른 강화. `hpPerMinute: 0.1` → 10분에 등장한 적의 체력 2배

### `src/config/boss.ts` — 보스 '잿불 군주'
| 값 | 바꾸면 |
| --- | --- |
| `hp` | **보스전 길이 = 승리 시각을 가장 크게 좌우**. 현재 7200 |
| `phase2At` | 이 비율 이하 체력에서 2페이즈(공격 간격 단축, 탄막 2연발, 소환 추가) |
| `attackCooldown: [1페이즈, 2페이즈]` | 공격 사이 대기. 줄이면 어려워짐 |
| `patterns` | 페이즈별 사용 패턴 목록 (`ring` 불씨 고리 / `charge` 돌진 / `meteor` 낙화 장판 / `summon` 소환) |
| `ring`, `charge`, `meteor` 의 `windup`·`delay` | 공격 예고 시간. 늘리면 피하기 쉬움 |

### `src/config/progression.ts` — 경험치 곡선
- 레벨 L→L+1 필요 경험치 = `round((xpBase + xpGrowth × (L-1)^xpExponent) × earlyScale[L-1])`
  - `earlyScale`: 초반 레벨 배율 목록. 현재 `[0.36, 0.5 ×4, 0.6, 0.7, 0.8, 0.9]` → Lv1은 36%, Lv2~5는 절반, Lv10 부터 원래 값. 값을 낮추면 초반 레벨업이 빨라짐 (현재 첫 레벨업 약 20초)
  - `xpBase` ↑ → 모든 레벨업이 조금씩 늦어짐
  - `xpGrowth`, `xpExponent` ↑ → 후반 레벨업이 느려져 보스전까지의 강화 수가 줄어듦 (기준 영구 강화로 봇 6판을 실행했을 때 보스에 도달한 판의 중앙값은 Lv 36)
- `baseRerolls`: 판마다 기본 새로고침 횟수 (2)
- `choiceCount`: 레벨업 후보 수 (3)
- `fallback`: 선택 가능한 일반 강화가 없을 때 사용하는 대체 선택지(응급 처치)

### `src/config/upgrades.ts` — 일반 강화 11종
- `effects`: `{ stat, op, value }` — `value` 는 일반 등급 값. `add` 는 더하기, `pct` 는 %(합산 후 곱), `mul` 은 곱하기
  - `gradeValues: [일반, 희귀, 영웅, 전설]` 을 주면 등급 배율 대신 그 값을 씀 (투사체 수처럼 정수가 필요한 효과)
- 일반 강화는 횟수 제한 없이 중첩됩니다. 특수 무기는 `maxStacks`(Lv 3)에 도달하면 강화 후보에서 제외됩니다.
- `healOnPick`: 고르는 즉시 회복량 (등급 반영)

### `src/config/grades.ts` — 레벨업 보상 등급
- `GRADES`: 등급별 `mult`(효과 배율), `weight`(기본 확률 %), `luckShift`(행운 1 당 확률 변화), `color`(카드 색)
- `GRADE_CONFIG.luckPerLevel`: 레벨당 행운 증가 (현재 0.06 → Lv 18 에서 행운 +1). `minCommonWeight`: 일반 등급 최소 확률

### `src/config/drops.ts` — 처치 드랍 아이템
- `DROPS`: 아이템별 처치 1회당 확률(`chance`). 위에서부터 판정해 한 번에 최대 1개
- `DROP_CONFIG`: 엘리트 확정 드랍, 회복량(25), 폭탄 피해(200)·범위(화면 크기), 바닥 유지 시간(20초), 동시 최대 개수(8)

### `src/config/meta.ts` — 토큰과 강화 상점
- `TOKEN_REWARDS`: 생존 1분당·처치 N마리당·엘리트당·승리 보너스 토큰
- `META_STATS`: 영구 능력치 강화 — 단계당 변화율(`pctPerLevel`, 음수는 감소), 최대 단계, 단계별 가격(`costs`)
- `META_UNLOCKS`: 해금 — 새로고침 +1, 부활, 시작 강화, 행운 +1 의 단계·가격
- `BALANCE_REFERENCE_META`: **밸런스 기준 상태**(토큰 145개 사용). `npm run sim` 기본값과 밸런스 회귀 테스트가 이 상태로 13분 30초~15분 승리를 확인함

### `src/config/player.ts` — 플레이어 시작 능력치·자동 전투
- 계산 순서: **시작 능력치 → 영구 강화(meta.ts) → 이번 판 강화(upgrades.ts × 등급)**. 상태창(Tab)에 세 단계가 그대로 표시됨
- v0.3.0 시작값: 체력 70, 공격력 9, 공격 속도 1.2회/초, 이동 속도 190, 회피 재사용 3.0초, 흡수 범위 75, 경험치 배율 1
- `AUTO_COMBAT.enabled`: `true`(기본)면 가장 가까운 적을 자동 조준·공격. `false` 로 바꾸면 마우스 조준 + 좌클릭 유지 공격으로 돌아감
- `AUTO_COMBAT.range`: 자동 조준 거리. 늘리면 멀리 있는 적부터 맞추기 시작함(투사체 사거리 `projectileRange` 보다 짧게 유지)

최대 체력, 이동 속도, 피해량, 공격 속도(`fireRate`), 투사체 수·속도·사거리, 회피 대기시간·지속·무적 시간, 피격 후 무적, 경험치 흡수 범위 등. 강화는 이 값을 기준으로 계산됩니다.

### `src/config/arena.ts` — 아레나·카메라
아레나 크기(`width`/`height`), 적 생성 거리(`spawnDistance` — 화면 밖에서 나타나도록), 화면 논리 해상도(`VIEW_CONFIG`).

### `src/config/dev.ts` — 개발용 '보스 직전 시작' 빌드
`bossPreset` 은 보스전을 빠르게 검증하기 위한 고정 예시 빌드입니다. 밸런스를 바꾸면 `npm run sim` 의 "보스 등장 시 레벨"을 보고 함께 맞춰 주세요.

## 밸런스 조정 절차

1. `src/config/` 값을 수정
2. `npm run sim` — 봇 20판 요약을 봅니다(수 초). 옵션: `npm run sim -- --runs 50 --skill 0.5 --seed 2000 --meta ref`
   - `--meta ref`(기본, 밸런스 기준) / `none`(영구 강화 0) / `max`(전부 구매)
   - 확인할 줄: `승리 시각`(목표 13:30~15:00), `첫 레벨업 중앙값`(목표 약 20초), `보스 등장 시 레벨`, `판당 토큰`, 사망 원인 분포
3. `npm test` — `tests/balance.test.ts` 가 15분 설계에서 벗어나면 실패합니다(의도한 변경이면 테스트 기준도 함께 수정)
4. `npm run dev` 로 직접 플레이 (개발 모드에서 시드 고정·보스 직전 시작 활용)
5. 측정 결과를 `docs/PLAYTEST.md` 에 기록

## 개발 모드

`npm run dev` 이거나 URL 에 `?dev=1` 을 붙이면 켜집니다(배포 빌드에서도 URL 로 켤 수 있지만 평소엔 숨겨져 있음).

| URL 예시 | 효과 |
| --- | --- |
| `?dev=1&seed=1234` | 시드 고정 → 같은 입력이면 스폰 순서·위치 난수와 강화 후보가 그대로 재현됨 |
| `?dev=1&start=boss` | 보스 등장 5초 전(13:25)부터, `config/dev.ts` 의 대표 빌드(Lv 18)로 시작 |
| `?dev=1&start=880` | 지정한 전투 시각(초)부터 시작 (시간 초과 테스트 등) |
| `?dev=1&god=1` | 무적 |

타이틀 화면의 '개발 모드' 패널에서도 시드·시작 구간·무적을 바꿀 수 있습니다. 결과 화면에는 항상 그 판의 시드가 표시되므로 버그 제보 시 함께 적어 주세요.
**보스 직전 시작·무적·시작 시각 지정을 쓴 판은 최고 기록에 반영되지 않습니다.**

개발 모드에서는 콘솔에서 `window.__rift.snapshot()` 으로 현재 상태를 볼 수 있습니다(자동 테스트도 이것을 사용).

### 시드 재현 범위
난수는 용도별로 분리되어 있습니다: 스폰(`spawn`), 강화 후보(`upgrade`), 보스 패턴(`ai`).
- 스폰 난수는 플레이어 행동과 관계없이 항상 같은 순서로 소비되므로, 같은 시드면 **적 종류·등장 시각·등장 방향/거리 난수**가 같습니다(실제 좌표는 플레이어 위치 기준).
- 강화 후보는 같은 시드에서 **같은 선택을 하면** 같은 후보가 나옵니다.

## 저장 데이터

`localStorage` 의 `rift-arena/save` 키에 JSON 으로 저장합니다.

```json
{ "version": 2, "settings": { "volume": 0.6 },
  "records": { "runs": 3, "wins": 1, "bestSurvival": 862.5, "bestKills": 1180, "fastestWin": 862.5 },
  "meta": { "tokens": 42, "totalEarned": 180, "purchases": { "hp": 2, "damage": 1, "reroll": 1 } } }
```

- 버전 1 데이터는 불러올 때 버전 2로 자동 변환됩니다(음량·기록 유지, 토큰 0). 구매 내역은 항목·최대 단계를 검증해 잘못된 값은 버립니다.

- 값이 없거나, JSON 이 깨졌거나, 버전이 다르면 **기본값으로 실행**합니다(게임이 멈추지 않음). 일부 필드만 잘못되면 그 필드만 기본값으로 바꿉니다.
- 저장소 접근이 막힌 환경(일부 비공개 모드)에서도 저장 없이 정상 실행됩니다.
- 저장 형식을 바꿀 때: `src/storage/save.ts` 의 `SAVE_VERSION` 을 올리고 `migrate()` 에 이전 버전 변환을 추가한 뒤 `tests/save.test.ts` 에 테스트를 추가하세요.
