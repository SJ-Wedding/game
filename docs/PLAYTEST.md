# 플레이 시간 측정·검증 기록

목표: **표준 난이도의 성공적인 플레이가 전투 시간 14:00~15:00 에 끝난다**, **첫 레벨업은 약 1분 이내**.

## 측정 방법
1. **헤드리스 시뮬레이션** (`npm run sim`): 자동 플레이 봇(`src/core/bot.ts`)이 브라우저 없이 같은 전투 규칙으로 끝까지 플레이. 시드 40개 × 봇 숙련도 3단계.
2. **실제 브라우저 실시간 플레이** (`npm run test:e2e:full`): 배포용 빌드를 Chromium 에서 열고, 봇이 매 프레임 DOM 키보드·마우스 이벤트(WASD·마우스 이동·좌클릭 유지·Space·카드 클릭)를 발생시켜 15분을 실시간으로 플레이. 개발 옵션(무적·보스 직전 시작) 미사용.

> 두 측정 모두 사람 대신 봇이 플레이한 결과입니다. 사람 플레이어 표본 측정은 아직 하지 않았습니다(아래 '남은 확인 항목').

## 2. 실제 브라우저 실시간 플레이 (v0.1.0 빌드 — 자동 전투 이전)

환경: 헤드리스 Chromium(소프트웨어 렌더링, 약 20fps), 배포 빌드(`vite preview`), 봇 입력 초당 약 20회.

| 시드 | 결과 | 종료 시각(전투) | 실제 경과 | 첫 레벨업 | 보스 등장 | 보스 등장 시 Lv | 처치 | 비고 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 1003 | 패배 — 가시 포자의 독침 | 13:39 | 13:41.6 | 38.6초 | 13:30.1 | 18 | 1114 | 보스 체력 85% 남은 상태에서 사망 |
| 1011 | 패배 — 가시 포자의 독침 | 11:12 | 11:15.9 | 38.1초 | — | — | 757 | Lv 15, 보스 등장 전 사망 |

한계:
- 두 판 모두 보스를 잡지 못하고 **가시 포자의 독침**에 사망. 브라우저 봇은 약 20fps·8방향 키 입력이라 시뮬레이션 봇(초당 60회·아날로그 이동)보다 회피가 서툴고, 시뮬레이션에서도 사망 원인 1위가 독침. 사람 플레이 테스트에서 독침이 과하게 느껴지면 `src/config/enemies.ts` 의 `spitter.projectileDamage`·`fireInterval` 부터 조정 권장.
- 이 실측은 자동 전투 도입 전 빌드에서 했음. v0.2.0 실시간 재측정은 남은 항목.

확인된 것:
- 전투 시간과 실제 시간이 일치(1003: 819.6초 vs 821.6초, 1011: 672.0초 vs 675.9초 — 차이는 시작·종료 처리 시간). 저프레임(20fps)에서도 시간이 느려지거나 튀지 않음.
- 첫 레벨업 38.6초·38.1초, 보스 13:30 등장, 보스 등장 시 Lv 18 — 시뮬레이션 예측과 일치.
- 15분 동안 페이지 오류 없음.

> 처음에는 Playwright 원격 입력(키 누르기·마우스 이동 명령)으로 조작했으나, 헤드리스 렌더링 부하 때문에 초당 4회밖에 반응하지 못해 1:32 에 사망했습니다. 사람의 반응 속도와 너무 달라 측정에서 제외하고, 페이지 안에서 매 프레임 입력 이벤트를 보내는 방식으로 바꿨습니다.

## 4. 남은 확인 항목
- **v0.2.0(자동 전투) 실시간 15분 재측정**: `FULL_RUN_SEEDS=1003,1011 npm run test:e2e:full`
- **사람 플레이어 측정**: 봇이 아닌 사람 3~5명이 표준 플레이로 몇 분에 끝나는지, 승률은 어떤지.
- **실제 탭 전환**: 테스트 환경에서는 실제 탭 전환이 불가능해 `visibilitychange` 이벤트를 모의했습니다. 실제 브라우저(Chrome·Edge·Firefox·Safari)에서 다른 탭으로 갔다 돌아오는 동작 확인 필요.
- **GPU 브라우저 성능**: 소프트웨어 렌더링 약 20~24fps에서만 측정. 일반 PC 브라우저에서 60fps 유지 여부, 적 64마리 + 탄막 상황 프레임 확인 필요.
- **효과음**: 헤드리스 환경이라 소리를 직접 듣지 못함. 음량 슬라이더 저장은 검증했으나 실제 소리 확인 필요.
